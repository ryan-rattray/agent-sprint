# Week 8, Day 1 — Step 0: Pick and Freeze (Monday, Nov 23)

## The idea

The capstone was deliberately left open all sprint, and today is why: Step
0. You review the candidates file against the selection criteria you wrote
before Week 8, pick one, and freeze it. The pick becomes a capstone sprint
inside the overall sprint, with its own done criteria. The list closes; new
ideas go back to the parking lot. Today's deliverable is the decision plus
a one-page capstone sprint sheet. No code until the freeze is recorded.

## What you'll build

The frozen pick, recorded in `capstone-candidates.md` (winner marked, list
closed), plus a one-page capstone sprint sheet: the question, an
architecture sketch, and binary done criteria for Friday.

## Steps

1. **Re-read the candidates file** and the selection criteria. Score each
   candidate honestly against all four criteria, in writing.
2. **Pick one.** Record the pick and the reasoning in the file. Close the
   list.
3. **Write the capstone sprint sheet.** Question, architecture, binary done
   criteria for Friday, and what "demo-able" means concretely.
4. **Commit.** `week-08 day-01: capstone frozen`. Breakage log (decisions
   count as findings).

## Done criteria (binary)

- [ ] One candidate is picked, recorded with reasoning, and the list is
      closed.
- [ ] A one-page capstone sprint sheet exists with binary done criteria
      for Friday.

## What this unlocks

- **Tue-Wed:** the build, against the frozen plan.
- **Thu:** Thanksgiving. Light by design.
- **Fri:** eval, write-up, demo.

## Likely snag

**Picking without scoring.** If the pick is "the one I'm excited about,"
run it through the criteria anyway. Excitement is data, not a decision
procedure. The criteria exist so the pick survives contact with Wednesday.

## When you're done

Reply "Day 1 done". Tomorrow's sheet: the first vertical slice.
